## Как проводились замеры

Матрицы хранятся в одномерных `vector<double>`, элемент `(i, j)` берётся как `A[i * N + j]`. Значения элементов от 1.0 до 1.9.
Для проверки результат каждого варианта сравнивается с результатом `ijk`, допустимая относительная погрешность 1e-12. Все варианты дали одинаковый результат.
Перед замером делается 2 прогревочных умножения (для N = 1760 одно, так как оно долгое). Потом умножение повторяется, пока суммарное время не станет больше 1 секунды, и берётся среднее время одного умножения. Матрица C обнуляется перед каждым умножением, это время не учитывается.

| N | Размер трёх матриц (MB)| |
|---|---|---|
| 160 | 0.6 MB | меньше L2 |
| 480 | 5.3 MB | между L2 и L3 |
| 832 | 15.8 MB | между L2 и L3 |
| 1760 | 70.9 MB | больше L3 |

## Объяснение

Матрицы хранятся по строкам, поэтому элементы одной строки лежат в памяти подряд, а элементы одного столбца далеко друг от друга (на расстоянии N элементов). Из памяти в кэш данные загружаются кэш-линиями по 64 байт (по 8 чисел).
Если идти по памяти подряд, то одна загруженная линия используется 8 раз, и процессор может заранее подгружать следующие данные. Если идти по столбцу, то каждое обращение попадает в новую кэш-линию, и из неё используется только одно число.
Скорость меняется в зависимости от цикла:

- **ikj, kij**: Лучший случай, когда B и C читаются по строкам подряд и переменная A[i][k] в цикле не меняется. 
- **ijk, jik**: Случай посередине по времени, когда A читается по строке, а B по столбцу
- **jki, kji**: Худший случай, когда A и C читаются по столбцам.

Результаты:

- При **N = 160** все матрицы помещаются в L2, поэтому даже чтение по столбцам не сильно тормозит. Худший вариант медленнее лучшего примерно в 2 раза.
- При **N = 480 и 832** матрицы уже не помещаются в L2, данные приходят из L3. Разница выросла примерно до 5.5 раз.
- При **N = 1760** матрицы не помещаются даже в L3, и данные приходится брать из оперативной памяти. 

Также видно, что jik быстрее ijk при больших N. В jik один столбец B используется для всех строк A подряд и успевает остаться в кэше, а в ijk вся матрица B заново читается по столбцам для каждой строки.

## Выводы

Лучше всего работают варианты **ikj** и **kij**, немного лучше ikj. В них внутренний цикл идёт по строкам матриц, поэтому кэш используется эффективно. Хуже всего работают **jki** и **kji**, где внутренний цикл идёт по столбцам.

Количество операций во всех вариантах одинаковое, но время отличается до 21 раза. Значит, для больших матриц главное — порядок доступа к памяти. Для матриц, хранящихся по строкам, внутренним лучше делать цикл по `j`, то есть использовать порядок ikj.
