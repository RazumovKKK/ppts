# Параллельное блочное умножение матриц (OpenMP)

Умножение квадратных матриц $C = A \times B$ блочным алгоритмом, также добавил распараллеливание через OpenMP. Сравнение с последовательным умножением в порядке `ikj`.

## Архитектура компьютера

| Параметр | Значение |
|---|---|
| CPU | Intel Core i7-12700H: 6 P-ядер (с Hyper-Threading) + 8 E-ядер, 20 логических процессоров |
| L1d (P-ядро) | 48 KB |
| L2 (P-ядро) | 1.25 MB |
| L3 (общий) | 24 MB |
| Компилятор | MSVC 19.37.32825 (Visual Studio 2022) |
| Флаги | `/O2 /openmp /EHsc`, конфигурация Release x64 |
| OpenMP | 2.0 (`/openmp` в MSVC) |

## Алгоритм

Матрицы хранятся в одномерных массивах в row-major порядке, элемент $(i, j)$ лежит по индексу `i * n + j`.

**`mul_ikj`** — умножение матриц из прошлой домашки

**`mul_block`** — блочное умножение (взял из лекции) + добавил распараллеливание.

**Распараллеливание.** (просил помощи у иишки) `#pragma omp parallel for schedule(static)` стоит на внешнем цикле по `i`. 
Каждый поток работает с непересекающимися кеш-линией матрицы C `bs` строк.

Указатели `a`, `b`, `c` на данные векторов передаются в `firstprivate`, чтобы у каждого потока была своя копия в регистре.

## Данные эксперимента

Матрица C обнуляется перед каждым запуском, это время в общее время не включено. Результат сравнивался с бейзлайном `mul_ikj`.
Погрешностью считается, если ошибка выше $10^{-12}$. Размеры блока: 32, 64, 128. Число потоков: 1, 2, 4, 6, 8, 12, 16, 20.

Размер блока выбран по размеру кэша.

## Выводы

- Наибольший выигрыш получается при N = 1760, когда матрицы не помещаются в L3. В обычном `ikj` для каждой строки A вся матрица B заново читается из оперативной памяти. В блочном варианте блок B загружается в кэш один раз и используется для всех строк блока A.
- BS = 32 лучший во всех экспериментах. Три блока 32×32 занимают 24 KB и поэтому они хранятся в L1d (48 KB). При BS 64 и 128 данные хранятся в L2, у которого задержка в несколько раз больше.
- Когда матрица маленькая (например, при N=160) одно умножение занимает доли миллисекунды, остальное время занимают загрузка данных и др. результат 0.340 мс при p = 6.

- Ускорение относительно p = 1 при N = 1760, BS = 32:

| p | 2 | 4 | 6 | 8 | 12 | 16 | 20 |
|---|---|---|---|---|---|---|---|
| ускорение | 2.04 | 3.52 | 4.47 | 4.57 | 5.18 | 5.35 | 5.14 |
.

## Выводы

По результатам эксперимента можно сделать вывод, что блочное умножение дает выигрыш при большом объеме данных. Когда всё помещается в L2, выигрыш небольшой.
Оптимальный размер блока достигается, когда все три блока помещаются в L1d. На моем компьютере это 32.
Путем распараллеливания масштабируется почти линейно до числа P-ядер (6). Дальше прирост ограничен архитектурой моего компьютера.
